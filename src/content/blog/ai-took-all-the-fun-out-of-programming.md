My first job as a software engineer was in 2016. It was an apprenticeship contract. Before that, I coded several little games just for the pleasure of building something with my "hands". Or my brain, I could say. It was quite fun. 

This is a pretty common story.

We all remember the satisfaction of building a program and seeing it run for the first time, and of resolving bugs after hours spent trying to find the problem. 

Well it's not news that it's all over now. 

I wouldn't say it's entirely my boss's fault. At the beginning of the year, I had this meeting with another colleague of mine and the CTO. We took one day to figure out what to do and how to properly implement AI in our workflow. 

To be more precise, we were already using AI last year but more in a casual way. You know those little prompts we write in Cursor because we're lazy to center this `<div>`, or to make the UI a little bit nicer. 

But we knew that 2026 would be a turning point.  

January-February marked a peak as more and more new tools to help developers industrialize their use of AI were appearing. We weren't talking about vibe coding anymore. It was all about spec-driven development. As it always has been, in a way. 

I remember at the end of this AI day, I'd never felt so overwhelmed and tired. I read so many articles about new ways to use AI. And the most disturbing thing was that, now, tools to improve AI development were built with AI as were their documentation, and the articles about them. It was a quantity of information a human brain couldn't process, or at least, not in a lifetime. 

So we started to use some tools. And we were jumping from one to another, month after month… and then week after week.

Now we have a pretty large panel of tools, most of which aren't used at all. But still, we have the possibility to:

- take a ticket
- ask Claude for a plan in an artifact we can comment on
- tell Claude to code, and test in a browser
- create a PR and to simplify it to remove all duplicate new code
- watch ci and fix bugs
- and produce a video showing the implementation so we can watch it

I no longer interact with the user interfaces I build. Claude does that for me and in a better way, as it notices all the edge cases and proposes fixes. But also has good enough default rules for UI/UX design that most of our users will be happy enough to use it.

And yet. I'm not a developer anymore. I'm more of a Factorio player, trying to optimize the pipeline for feature production.

That's how I can have my fun now. Trying to build all the pipelines, the ecosystem around developing with AI.

After all, software engineering just moved its cursor to another domain: productivity engineering. We're no longer asked to write pieces of code, even if it was fun, and it is still important to know how to code, but we've become another kind of engineer. 

A process engineer optimizes and improves the efficiency of an organization’s manufacturing and industrial processes. Well, in that case, have we become process engineers?
